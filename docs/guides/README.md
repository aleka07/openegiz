# Гайды по установке OpenEgiz

Это пошаговые инструкции: как развернуть OpenEgiz с нуля на ARM64-машине зимней школы и что с этим стендом делать дальше.

Гайды — **инструкции, а не хроника**. Каждый можно выполнить сверху вниз на чистой машине. Истории вида «а вот здесь всё сломалось, и мы три часа разбирались почему» живут отдельно, в [install-log.md](../install-log.md) — гайды на них ссылаются там, где это помогает понять «почему именно так».

## Быстрый старт для нетерпеливых

Если k3s и Helm уже есть, а образ extended API уже собран:

```bash
make install     # helm-релиз "opentwins" в namespace "opentwins"
make status      # ждём 14/14 Running (~1 минута на быстром хосте)
make endpoints   # адреса Grafana, Ditto, InfluxDB, MQTT
```

Grafana (она же UI OpenEgiz) — порт **30718**, логин `admin` / `admin`.

## Три вещи, которые ломают установку чаще всего

1. **Имя релиза должно быть `opentwins`.** Несколько значений в чарте ссылаются на производные от него имена. Makefile прибивает имя намеренно.
2. **Образ extended API надо собрать ДО `helm install`** — `rebuild/extended-api/build.sh` на самой arm64-машине. Тянуть его неоткуда, он существует только в локальном containerd.
3. **`-XX:MaxRAM` и `memoryMi` у сервисов Ditto связаны жёстко.** Меняете одно — меняйте второе тем же коммитом, иначе все пять сервисов Ditto уйдут в OOMKill-петлю.

## Дефолтные пароли

Grafana `admin:admin` · Ditto `ditto:ditto` (devops `devops:foobar`) · InfluxDB `admin:password` · MongoDB и Mosquitto — без аутентификации вообще.

Это дефолты чарта. Для учебного стенда **в LAN** приемлемо, наружу выставлять нельзя. Полный список эндпоинтов и оговорки — в гайде [03](03%20–%20Проверка%20и%20сквозной%20тест.md).
