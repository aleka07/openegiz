# 07. Эксплуатация: перезапуск, данные, восстановление

Стенд поставлен и работает. Этот гайд — про то, что делать дальше: что переживает выключение питания, где физически лежат данные, как безопасно перезапустить и обновить релиз, и на что смотреть, когда «что-то не так».

## Отключение питания: проверено на реальном случае

Вся стойка GX10 обесточилась посреди дня. Незапланированно, зато это оказался идеальный тест на устойчивость.

### Что поднялось само, без единого ручного действия ✅

- **k3s и Docker.** Оба systemd-юнита `enabled`, после загрузки оба `active`, нода `Ready`.
- **Все 14 подов вернулись в `Running` самостоятельно.** Счётчики рестартов: у большинства =1 (сама загрузка), у Grafana =3, у Telegraf =4 — это те же безобидные гонки старта, что и при первой установке (зависимость ещё не слушает порт), они самолечатся.
- **Данные целы.** Двойник `test:winterschool-1` со значением 46.1 нашёлся в MongoDB, ряды в InfluxDB на месте, база Grafana и плагины не пострадали. Это не везение: Mongo (журнал WiredTiger), InfluxDB (WAL) и kine k3s (SQLite) по устройству crash-safe. `dmesg` показал ноль ошибок ext4.
- **Локально собранный образ `openegiz/ditto-extended-api` уцелел** в хранилище containerd k3s — он лежит на диске в `/var/lib/rancher`.
- **NTP пересинхронизировался** — для временных рядов это существенно.

Вывод: стенд к внезапному обесточиванию устойчив. Единственный оставшийся внешний фактор — настройка BIOS «restore on AC power» (в этот раз машина поднялась сама) и офисная сеть; ни то, ни другое из ОС не контролируется.

### Странность, о которой надо знать: LAN против VPN

После аварии машина сохранила LAN-адрес `<host-ip>`, но с рабочей станции была доступна **только по VPN** (`<vpn-ip>`). Проблема была на сетевом пути вне машины — офисная сеть тоже пережила отключение.

Практический вывод: держите в `~/.ssh/config` обе записи и в скриптах пробуйте обе:

```text
ssh gx10-11        # LAN
ssh vpn-gx10-11    # VPN
```

## Где лежат данные

Всё персистентное — в PersistentVolumeClaim'ах в namespace `opentwins`, на провайдере `local-path` k3s (то есть физически на NVMe самой машины, под `/var/lib/rancher/k3s/storage/`).

```bash
kubectl get pvc -n opentwins
```

| Что | PVC | Что там |
|---|---|---|
| InfluxDB 2 | `opentwins-influxdb2` | временные ряды телеметрии |
| MongoDB | `data-opentwins-mongodb-0` | двойники, политики, connections Ditto |
| Grafana | PVC чарта Grafana (`persistence.enabled: true`) | БД Grafana, дашборды, распакованные плагины |

Две вещи стоит запомнить:

- **PVC MongoDB называется `data-opentwins-mongodb-0`,** потому что это StatefulSet. У прежнего bitnami-чарта был обычный PVC `opentwins-mongodb` — если такой ещё лежит на машине, это осиротевший том со старой установки, данные из него автоматически не переезжают.
- **PVC Grafana — это ещё и кэш плагинов.** Он же обеспечивает офлайновую загрузку без интернета (гайд [04](04%20–%20Grafana-плагины.md)). Снесёте его — следующий старт потребует сети.

Образы, включая локально собранный extended API, живут отдельно от PVC — в containerd-хранилище k3s. `helm uninstall` их не трогает.


## Перезапуск одного компонента

Правильный способ — рестарт rollout'ом, а не удалением пода:

```bash
kubectl rollout restart deployment/opentwins-ditto-extended-api -n opentwins
kubectl rollout status  deployment/opentwins-ditto-extended-api -n opentwins
```

Для MongoDB и InfluxDB (это StatefulSet'ы):

```bash
kubectl rollout restart statefulset/opentwins-mongodb -n opentwins
```

Rollout поднимает новый под и только потом убирает старый; `kubectl delete pod` создаёт окно простоя без всякой пользы.

## Апгрейд релиза

```bash
make upgrade
# = helm upgrade opentwins . -n opentwins --wait --timeout=15m --debug
```

Что надо знать до того, как нажать:

- **Имя релиза остаётся `opentwins`.** Несколько значений ссылаются на производные от него имена (та же конфигмапа `opentwins-telegraf-real-config`).
- **Меняете `resources.memoryMi` у сервисов Ditto — меняйте `-XX:MaxRAM` тем же коммитом.** Эти два значения связаны жёстко, рассинхрон возвращает OOMKill-петлю из гайда [02](02%20–%20Установка%20платформы%20на%20ARM64.md).
- **Проверяйте, что оверрайд доехал**, прежде чем деплоить:

  ```bash
  helm template opentwins . -n opentwins | grep -A2 'memory'
  ```

  Helm молча выбрасывает значения, не совпадающие ни с одним ключом сабчарта. Именно так когда-то потерялась правка `thingssearch` вместо `thingsSearch` — ни warning, ни ошибки.
- **`initChownData` должен оставаться выключенным.** Иначе апгрейд Grafana падает в `Init:Error` — разбор в гайде [04](04%20–%20Grafana-плагины.md).

Апгрейд идёт без простоя: старый под продолжает обслуживать, пока новый не поднялся. При проблеме с init-контейнером старый под просто продолжает работать (так и было при первом апгрейде с плагинами).

## Полная переустановка

`helm uninstall` оставляет за собой ресурсы двух видов, и оба надо убрать руками:

```bash
helm uninstall opentwins -n opentwins
#   -> "These resources were kept due to the resource policy: [PersistentVolumeClaim] opentwins-influxdb2"
kubectl delete pvc --all -n opentwins     # включая тот самый PVC influxdb
kubectl delete job --all -n opentwins     # post-install hook переживает uninstall
kubectl delete pod --all -n opentwins --force --grace-period=0
kubectl get all -n opentwins              # проверить, что реально пусто
```

**PVC надо сносить осознанно.** InfluxDB уже отработала одноразовый bootstrap админа/бакета/токена на своём томе; установка поверх инициализированного тома — классический источник загадочных ошибок «на втором запуске». Если данные нужны — снимайте бэкап до удаления, а не после.

Локально собранный образ extended API удалять не надо — он в containerd и переживает переустановку.

## Что считать нормой, а что тревогой

| Наблюдение | Норма? | Что делать |
|---|---|---|
| `opentwins-telegraf` с `RESTARTS 2` после установки | ✅ да | Telegraf стартовал раньше, чем mosquitto начал принимать TCP. Само лечится на третьем старте. Тревога — если счётчик **продолжает расти** |
| `RESTARTS` у Grafana/Telegraf выросли после ребута | ✅ да | те же гонки старта |
| `helm-install-traefik` с `RESTARTS 2`, статус `Completed` | ✅ да | штатная гонка бутстрапа k3s. Тревога — если вместо `Completed` он в `CrashLoopBackOff` |
| `GET /api/2/connections` возвращает `[]` | ✅ да | особенность Ditto. Реальный статус — через devops piggyback, см. гайд [03](03%20–%20Проверка%20и%20сквозной%20тест.md) |
| `doesn't exist` в логах Telegraf на каждое сообщение | ✅ да | пути с `optional = true`, гайд [03](03%20–%20Проверка%20и%20сквозной%20тест.md) |
| `404` от extended API на `/` | ✅ да | роута `/` нет; 404 доказывает, что сервер слушает |
| Данные не появились в Grafana сразу после публикации | ✅ да | ~10 с задержки от `flush_interval` Telegraf |
| Ditto-под в `CrashLoopBackOff`, `OOMKilled`, exit 137 | ❌ нет | рассинхрон `MaxRAM` / `memoryMi`, гайд [02](02%20–%20Установка%20платформы%20на%20ARM64.md) |
| Extended API в `ImagePullBackOff` | ❌ нет | образа нет в containerd либо `pullPolicy` не `IfNotPresent`, гайд [02](02%20–%20Установка%20платформы%20на%20ARM64.md) |
| Grafana в `Init:Error` на `init-chown-data` | ❌ нет | включился `initChownData`, гайд [04](04%20–%20Grafana-плагины.md) |
| Grafana стартует без плагинов / init падает на wget | ❌ нет | недоступны vendored zip и нет кэша на PVC, гайд [04](04%20–%20Grafana-плагины.md) |

## Безопасность

### Что закрыто 2026-08-07

1. **MongoDB убрана из сети.** `plainMongodb.service.type: ClusterIP` — NodePort 30717 больше не слушается. Все потребители ходят в Mongo по внутрикластерному DNS. Для разовой инспекции: `kubectl port-forward -n opentwins svc/opentwins-mongodb 27017:27017`.
2. **Все дефолтные учётки ротированы** — Grafana `admin/admin`, Ditto `ditto:ditto` и `devops:foobar`, InfluxDB `admin/password` и опубликованный в репозитории админ-токен InfluxDB больше не действуют; старый operator-токен удалён из InfluxDB.
3. **Секретов в репозитории нет.** `values.yaml` содержит невалидные плейсхолдеры, реальные значения живут только на хосте:
   - `~/openegiz-deploy/secrets.values.yaml` — helm-оверрайд (600);
   - `~/course/CREDENTIALS.md` — таблица «система / логин / пароль / где используется» (600);
   - `~/.config/openegiz-mcp.env` — рантайм Hermes (600).

   Деплой всегда с оверрайдом: `helm upgrade opentwins <chart> -n opentwins -f ~/openegiz-deploy/secrets.values.yaml`. `make upgrade` подставляет его сам и падает, если файла нет.
4. **У Hermes больше нет админского токена InfluxDB** — только read-only на bucket `default` (проверено: запись → 403). Из MCP-сервера `openegiz-ditto` убран `set_feature_property` (прямая запись в двойник мимо потока данных); `publish_telemetry` оставлен намеренно.

Подробности и команды ротации — в [install-log.md](../install-log.md), раздел «Security pass перед школой».

### Что осталось открытым осознанно

1. **Mosquitto без аутентификации** (30511/31039) — кто дотянулся до порта, тот может писать в любой двойник. Оставлено намеренно: курс построен на том, что студент публикует MQTT с ноутбука одной командой.
2. **Ditto Extended API без аутентификации** на NodePort 30528 — плагин Grafana дёргает его из браузера студента, а в самом сервисе аутентификации нет. Значит, любой в LAN читает и пишет двойники через этот порт мимо паролей Ditto. Не чинилось: ingress с auth, сетевая политика или снятие NodePort ломают страницу Twins.
3. **Терминал Hermes работает прямо на хосте** (`terminal.backend: local`) — фильтр тулов ограничивает MCP, но не шелл.
4. **Учётки общие**, персональных нет — один стенд на всех.

Для LAN-стенда учебной школы это осознанный компромисс. За пределы LAN такое выставлять нельзя ни в каком виде.
