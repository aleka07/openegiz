# 06. JaamSim — дискретно-событийное моделирование

JaamSim — симулятор дискретных событий на Java. В курсе он отвечает за «что будет, если»: по модели производственной линии прогоняются сценарии, а результаты сравниваются с тем, что реально показывает цифровой двойник.

Как и pm4py, ставится **вне кластера**, в `~/course/jaamsim`.

Справочная заметка — [notes-course-tools.md](../notes-course-tools.md).

## Установка

```bash
mkdir -p ~/course/jaamsim && cd ~/course/jaamsim
curl -sSL -O https://github.com/jaamsim/jaamsim/releases/download/v2026-05/JaamSim2026-05.jar
sha256sum JaamSim2026-05.jar
```

Должно совпасть:

```text
be8229bbe0a545e1e4a10338aa66dfd3c9e23d933c6f65bc3baa904d6f8fceb9   19533050 байт
```

Это релиз `v2026-05`, опубликован 2026-07-06 — текущий последний стабильный.

## Java: ничего доставлять не надо

Манифест jar'а говорит `Created-By: 25+36-LTS (Eclipse Adoptium)` и несёт `Enable-Native-Access`, из чего легко сделать вывод, что нужен Java 24+. **Это не так.** Манифест фиксирует только тот JDK, которым jar *собирали*.

Реальный таргет читается из заголовка class-файла:

```bash
unzip -p ~/course/jaamsim/JaamSim2026-05.jar \
  'com/jaamsim/basicsim/JaamSimModel.class' | od -An -tu1 -N8
```

Мажорная версия байткода — **52, то есть Java 8**. Стоковый OpenJDK 8, который уже есть на gx10-11 (`/usr/lib/jvm/java-8-openjdk-arm64`, `1.8.0_492`), запускает самую свежую JaamSim без проблем — проверено запуском, а не только чтением байтов.

Итог: `openjdk-17-jre-headless` **не устанавливался**, `update-alternatives` **не трогался**. Новейшая JaamSim при нулевом изменении системы.

## Запуск: только `-headless`

Это главный практический вывод гайда, и он стоил трёх отдельных провалов.

**Провал 1 — справки нет.** `java -jar JaamSim2026-05.jar -h` не печатает **ничего** и выходит с кодом 0. Реальный список флагов пришлось доставать так: вытащить `com/jaamsim/ui/GUIFrame.class` из jar и прогнать `strings`. Нашлось: `-batch`, `-script`, `-zbuffer`, `-headless`, `-quiet`, `-safe_graphics`, `-optional_graphics`.

**Провал 2 — `-batch` это не headless.** И `-b`, и `-batch` всё равно конструируют Swing-GUI и умирают:

```text
Exception in thread "main" java.awt.HeadlessException:
No X11 DISPLAY variable was set, but this program performed an operation which requires it.
	at com.jaamsim.ui.GUIFrame.createInstance(GUIFrame.java:482)
```

GUI пропускает **только `-headless`**.

> **Самое неприятное: обе эти неудачи завершаются с кодом выхода 0.** Обёртка в CI или в скрипте не может полагаться на exit code — надо явно проверять, что файлы `.rep` / `.dat` действительно появились.

**Провал 3 — молча неправильные имена выходов.** В первой версии `CourseLine.cfg` в `RunOutputList` стояло `[WaitQueue].TimeAverage`. Такого выхода не существует. JaamSim не выдал ошибки — он записал **буквальный текст выражения** в колонку данных для каждой строки. Правильное имя — `[WaitQueue].QueueLengthAverage`.

Отсюда правило для методички: **всегда глазами сверяйте шапку `.dat` со значениями под ней.**

## Рабочий прогон

```bash
cd ~/course/jaamsim/models
java -jar ~/course/jaamsim/JaamSim2026-05.jar CourseLine.cfg -headless
```

Рядом с `.cfg` появляются:

- `CourseLine.rep` (~17 KB) — полный отчёт по каждой репликации: времена состояний, загрузка, распределение длины очереди и накопленные доли, сводка statistics-коллектора;
- `CourseLine.dat` (~419 B) — по строке на репликацию для записей `RunOutputList` плюс финальная строка «среднее ± СКО».

Содержимое `.dat` из проверенного прогона (3 репликации):

```text
Scenario Replication [PartStats].SampleAverage/1[min]  [WaitQueue].QueueLengthAverage  [Machine].Utilisation
1        1           2.346238757658468                1.5293214293516755              0.7913585537183333
1        2           2.4753701582103385               1.6793641707416689              0.8029958646016666

1                    2.4721382187690213  0.3088…      1.6779543663877823  0.3675…     0.8028137055327778  0.0282…
```

### Проверка не «файл появился», а «симулятор считает правильно»

В модели заявки приходят экспоненциально со средним 1 мин, обслуживание — равномерное на [0.70, 0.90] мин. Значит E[S] = 0.8 мин, и загрузка сервера аналитически:

```text
ρ = λ · E[S] = 1 · 0.8 = 0.80
```

Измеренное: **0.8028 ± 0.0282**. Плюс через сток за прогон в 10 000 минут проходит ~9.9–10.2 тысячи деталей. Совпадение с теорией — вот это и есть доказательство, что модель действительно симулирует, а не просто пишет файлы.

## Про саму модель

`models/CourseLine.cfg` — минимальная линия `EntityGenerator → Queue → Server → Statistics → EntitySink`. В ней **намеренно нет графических блоков** (`View`, `DisplayModel`, `Position`): конфиг с графикой headless тоже грузится нормально, но без неё учебный пример читается гораздо легче.

Что за что отвечает:

```text
Simulation PrintReport { TRUE }   -> порождает .rep
RunOutputList { ... }             -> порождает .dat
```

Готовых моделей для растаскивания на примеры полно внутри самого jar:

```bash
# ~20 учебных моделей: Factory Example с 10 нарастающими вариантами, Job Shop, Cafe
unzip -l ~/course/jaamsim/JaamSim2026-05.jar 'resources/examples/*'

# полное руководство пользователя
unzip -p ~/course/jaamsim/JaamSim2026-05.jar \
  'resources/documents/JaamSim User Manual.pdf' > /tmp/JaamSim-manual.pdf
```

## GUI: где его запускать

Всё, что описано выше, покрывает **только headless-батч**: прогоны, отчёты, репликации, перебор параметров. Редактор моделей (Swing + OpenGL) этим не покрыт вообще.

У студента, которому нужно построить или отредактировать модель, есть два пути:

1. **X11-форвардинг:** `ssh -X gx10-11`, затем `java -jar ~/course/jaamsim/JaamSim2026-05.jar model.cfg`. Требует X-сервер на своей машине: XQuartz на macOS, VcXsrv/X410 на Windows, на Linux — из коробки. **Этот путь не устанавливался и не тестировался.** 3D-вид в JaamSim — OpenGL, так что по X11 ждите софтверного рендеринга и тормозов; `-safe_graphics` помогает.
2. **Запустить jar у себя на ноутбуке.** Файл тот же самый, кроссплатформенный, нужен только JRE. **Рекомендуемый путь для авторства моделей**, а gx10-11 оставить под headless-прогоны и репликации.

Второй вариант почти всегда правильный: редактировать модель комфортнее локально, а считать — на машине с 20 CPU.
